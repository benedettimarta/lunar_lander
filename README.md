# Reinforcement Learning for Autonomous Lunar Landing

This project investigates reinforcement learning (RL) controllers for the **Gymnasium Lunar Lander** environment. The goal is to train an autonomous lander to reach the landing pad safely while reducing crashes, excessive control effort, high touchdown speed, and unstable attitude.

The project compares two reinforcement learning algorithms:

- **Deep Q-Network (DQN)**
- **Proximal Policy Optimization (PPO)**

It also includes:

- baseline training and evaluation;
- DQN vs PPO algorithm comparison;
- hyperparameter sensitivity analysis;
- reward-design sensitivity analysis;
- robustness testing under sensor and actuator uncertainty;
- automatic result plotting.

---

## 1. Project Goal

The main research question is:

> How can reinforcement learning be used to train an autonomous lunar lander controller, and how do algorithm choice, learning parameters, reward design, and uncertainty affect landing performance?

The project aims to analyse the learning process scientifically by comparing algorithms and evaluating how different design choices affect performance.

---

## 2. Environment Description

The project uses the `LunarLander` environment from Gymnasium.

In this environment, a lander must descend and land between two flags on a landing pad. The agent receives observations from the environment and chooses one discrete action at every time step.

### 2.1 State / Observation

The observation contains 8 values:

1. horizontal position;
2. vertical position;
3. horizontal velocity;
4. vertical velocity;
5. lander angle;
6. angular velocity;
7. left leg contact indicator;
8. right leg contact indicator.

### 2.2 Actions

The action space is discrete:

```text
0 = do nothing
1 = fire left orientation engine
2 = fire main engine
3 = fire right orientation engine
```

The controller must learn when to use these engines to land safely.

---

## 3. Algorithms

### 3.1 DQN

DQN is a value-based reinforcement learning algorithm. It estimates the expected future reward for each possible action and selects actions based on these values. Since Lunar Lander has a discrete action space, DQN is naturally suited to this task.

### 3.2 PPO

PPO is a policy-gradient reinforcement learning algorithm. Instead of estimating action values only, it directly learns a policy that maps states to actions. PPO is included as a comparison algorithm to investigate whether a policy-gradient method performs better or worse than DQN on this task.

```text
lunar_lander/
│
├── run.py
```

### Folder/file roles

```text
config.py
```
Stores all main settings: timestep budgets, seeds, algorithm hyperparameters, sensitivity-analysis settings, reward-shaping cases, and robustness cases.

```text
core.py
```
Contains shared helper functions and wrappers, including environment creation, reward shaping, sensor-noise wrapper, thruster-dropout wrapper, model creation, model loading, evaluation, and result saving.

```text
models/
```
Stores trained models, such as `baseline_dqn.zip` and `baseline_ppo.zip`.

```text
logs/
```
Stores training logs generated by the Monitor wrapper. These are used to plot learning curves.

```text
results/
```
Stores CSV and JSON files containing evaluation results.

```text
figures/
```
Stores automatically generated plots for the report.

## 9. Script Descriptions

### 9.1 `01_train_baselines.py`

Trains the baseline DQN and PPO models using the hyperparameters specified in `config.py`.

Run:

```bash
python 01_train_baselines.py
```

Outputs:

```text
models/baseline_dqn.zip
models/baseline_ppo.zip
logs/baseline_dqn/monitor.csv
logs/baseline_ppo/monitor.csv
results/baseline_dqn_evaluation.json
results/baseline_ppo_evaluation.json
```

Use this script first. All later analysis depends on these trained baseline models.

---

### 9.2 `02_evaluate_baselines.py`

Evaluates the saved DQN and PPO baseline models over multiple episodes.

Run:

```bash
python 02_evaluate_baselines.py
```

Outputs:

```text
results/baseline_algorithm_comparison.csv
results/baseline_dqn_reevaluation.json
results/baseline_ppo_reevaluation.json
```

This file is used to compare the baseline performance of DQN and PPO.

---

### 9.3 `03_sensitivity_analysis.py`

Runs hyperparameter sensitivity analysis for DQN and PPO.

Run:

```bash
python 03_sensitivity_analysis.py
```

DQN parameters tested:

```text
learning rate
discount factor gamma
final exploration epsilon
batch size
replay buffer size
target network update interval
neural network architecture
```

PPO parameters tested:

```text
learning rate
discount factor gamma
clip range
entropy coefficient
rollout length n_steps
batch size
neural network architecture
```

Outputs:

```text
results/sensitivity_individual_runs.csv
results/sensitivity_summary.csv
```

This is the most time-consuming script.

---

### 9.4 `04_reward_sensitivity.py`

Runs reward-design sensitivity analysis.

Run:

```bash
python 04_reward_sensitivity.py
```

Reward cases tested:

```text
original_reward
fuel_saving
attitude_stability
soft_landing
combined_shaping
```

This investigates how adding extra reward penalties changes the learned control strategy.

Outputs:

```text
results/reward_sensitivity_individual_runs.csv
results/reward_sensitivity_summary.csv
```

---

### 9.5 `05_robustness_evaluation.py`

Evaluates the trained baseline models under physically meaningful lunar-lander uncertainty cases.

Run:

```bash
python 05_robustness_evaluation.py
```

Robustness cases:

```text
nominal
low_sensor_noise
high_sensor_noise
low_thruster_dropout
high_thruster_dropout
combined_noise_dropout
```

This replaces wind testing because the Moon has essentially no atmosphere. Instead, the project tests uncertainty sources that are more realistic for a lunar lander:

- noisy navigation/state measurements;
- missed thruster commands;
- combined sensor and actuator uncertainty.

Outputs:

```text
results/robustness_summary.csv
results/robustness_dqn_<case>.json
results/robustness_ppo_<case>.json
```

---

Generates plots from the available result files.

Run:

```bash
python 06_plot_results.py
```

Possible outputs:

```text
figures/baseline_dqn_learning_curve.png
figures/baseline_ppo_learning_curve.png
figures/baseline_algorithm_reward.png
figures/baseline_algorithm_success.png
figures/baseline_algorithm_crash.png
figures/sensitivity_<algorithm>_<parameter>_reward.png

```

The script only plots results that already exist. For example, if reward sensitivity has not been run yet, reward-sensitivity plots will be skipped.

---

### 9.7 `07_watch_trained_agent.py`

Visualizes a trained model in the Lunar Lander environment.

Run:

```bash
python 07_watch_trained_agent.py --algorithm DQN
```

or:

```bash
python 07_watch_trained_agent.py --algorithm PPO
```

To test a disturbance visually:

```bash
python 07_watch_trained_agent.py --algorithm DQN --disturbance combined
```

Available disturbances:

```text
none
low_noise
high_noise
dropout
combined
```

This script is only for visualization. It is not necessary for numerical evaluation.

## 11. Reducing Runtime

If the project takes too long, edit `config.py`.

For quick testing:

```python
BASELINE_TIMESTEPS = 100_000
SENSITIVITY_TIMESTEPS = 50_000
REWARD_SENSITIVITY_TIMESTEPS = 50_000
SEEDS = [42]
```

For stronger final results:

```python
BASELINE_TIMESTEPS = 300_000
SENSITIVITY_TIMESTEPS = 150_000
REWARD_SENSITIVITY_TIMESTEPS = 150_000
SEEDS = [42, 123]
```

If there is enough time, using three seeds is even better:

```python
SEEDS = [42, 123, 999]
```
